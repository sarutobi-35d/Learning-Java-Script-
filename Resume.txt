RESUMÉ SUR LES NOTIONS

1. VARIABLES :
    const pour une variable qui ne sera jamais reassignée,
    let pour l'inverse,
    var est toujours un moyen de declaration (comme let) mais moins utilisé dans les nouvelles version de JavaScript.

CONCATENATION : le +, les back tic avec ${a} ${b} 
BOOLEAN : le type null et undefined(pour une variable non définie)

LES TABLEAUX : Permettent de save une liste de valeur. 
    * Un tableau peut contenir un autre tableau : const notes = [10, 9, 18, 'hello', [6, 7, 0]]

LES OBJETS : save les données un plus complexe que les tableaux en utilisant des clés
    * une personne : const person = {nom: "Fadil", prenom: "Scarlet"};

NB: En JavaScript, tous les types de variable sont des objets.


2. LES CONDITIONS: 
    permettent de tester quelque chose et de n'executer cette chose que si le test est verifié.
    * If... else
        * ===(les valeurs doivent etre identique(le meme type))
        * une chaine de carectère vide égale à false ('' == false)
        * Les opérateurs logiques ( ET et OU)
        * ! permet d'inversé un booléen (!true égale false)

    NB: Séparé les conditions pour faciliter la lisibilité et la maintenabilité du code.
    
    * switch case permet de verifier une variable à différente valeur.
    *prompt est une instruction d'écriture.


3. LA PORTÉE DES VARIABLES:
    Elles ne sont que accéssible dans la condition, boucle ou fonction dans laquelle elle est declaré. Sauf si le type est
    du type var... D'ou une raison de moins utilisé le type var.


4. LES BOUCLES:
    Permettent de repeter un morceau de code un certains nombre de fois en fonction de conditions.
        for of... Pour les objets itérable(Tableaux (Ex: for (let note of notes))), pour les valeurs
        for in sur les objets non itérable (for(let i in notes))


5. FONCTION: est un bloc de code reutilisable. Elle a plusieurs syntaxes de déclaration: 
    * Avec le mot clé function: elle peut etre appelée avant sa declaration, c'est le hoisting(la déclaration des fonctions 
    sont prises en compte avant l'éxexution du code). 
    * une declaration stockée dans une variable(const ou let): elle ne peut pas etre appellée avant sa declaration. 
    * les fonctions fléchées.
        * this fait appel à un objet global disponible sur la page... Coté navigateur.
        * Une fonction peut etre créee dans un objet/variable



6. CLASSES & PROTOTYPES: de manière générale, un prototype est une classe.


7. LES EXCEPTIONS: permet de déclancher des erreurs lorsque nous avons les données non attendues.
    *throw, try...catch


8. FONCTIONS USUELLES: ce sont des methodes que l'on peut utilisé sur des objets, variable, tableaux etc 
    pour effectuer des operations précises.
    
    * at sur les tableaux accepte les valeurs negative.

NB: Pour plus de fonctions usuelles, rendez-vous sur la documentation officielle


9. SUCRE SYNTAXIQUE: Terme utilisé pour désigner la facon d'ecrire plus simplement et rapidement du code(ce sont des 
    éléments de syntaxes)


10. LES TIMERS

    * Operation synchrone: attendre la fin de l'éxecution d'une tache avant de faire une autre.
    * Operation asynchrone: possibilité de faire une autre tache pendant qu'une autre est encours d'exécution.

    NB: L'un des plus grand problèmes de l'asynchrone est l'imbrication des callBacks, dans les cas ou il faut attendre un 
    certain temps pour les autres operations; et pour palier à cela, il existe le système de Promesse. Cette facon est 
    bloquante et se rapporte à la notion de synchrone.



11. PROMISE/PROMESSES: représenté n'importe quel code qui peux se derouler de manière asynchrone.

    En plus du système de callBacks avec then... pour le traitement asynchrone, on peut utilisé une fonction 
    asynchrone avec la méthode await devant l'appel des fonctions pour les traitements.



12. FETCH() Appel HTTP
    fetch() est une fonction JS qui utilise les Promise JavaScript nativement. Il permet de contacter un serveur 
    pour recupérer des informations(requetes HTTP coté Client/Navigateur), ou communiquer avec un serveur distant 
    ou une API.

    NB: Une reponse est considérée comme OK si son Statut est supérieur ou egal à 200 et inférieur à 400.

    


13. LES MODULES: permet de separé le code en plusieurs fichiers pour ainsi facilité la lecture et la maintenabilité 
    du code JS.


14. LES COMMENTAIRES & JSDoc: permet d'expliquer du code(rajouter du contexte, expliquer pourquoi une ligne a été ajouter) 
    JSDoc a pour syntaxe: /**
                            1ère ligne decrit par exemple ce que fait une fonction
                            2ème les paramètre
                            .
                            .
                            .
                            Jusqu'à N paramètres
                            autres lignes le type de retour
                           */
